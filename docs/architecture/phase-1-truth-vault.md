# Phase 1 — Truth Vault and Profile

Phase 1 adds a local, versioned candidate profile without enabling autofill or submission.

## Implemented

- Service-worker-owned storage in `chrome.storage.local`.
- Runtime validation on every side-panel profile message and stored vault value.
- Immutable profile revisions: each accepted edit retains the previous candidate snapshot.
- Manual editing for identity, contact details, public links, work history, education, skills, and work authorization.
- Explicit sensitivity levels, including `SENSITIVE` work-authorization facts.
- JSON backup and restore with a versioned envelope, malformed-input rejection, and direct-profile migration.
- Local PDF extraction with PDF.js and local DOCX extraction with Mammoth.
- A 5 MB résumé limit, SHA-256 source records, and no raw résumé retention.
- Conservative résumé parsing for identity, contact details, links, structured work and education lines, and skills.
- `VERIFIED_DOCUMENT` staging, explicit conflict decisions, and user verification before reuse as `VERIFIED_USER`.
- No inference of citizenship, visa status, disability, race, gender, veteran status, criminal history, or other sensitive attributes from résumé text.

## Data flow

```text
Side panel editor/file picker
  → runtime-validated message
  → extension service worker
  → schema-validated Truth Vault
  → chrome.storage.local
```

Résumé bytes stay in the side panel long enough to extract text and calculate a hash. The service worker receives only the structured draft and source metadata. Raw PDF and DOCX bytes are not stored.

## Conflict and verification rules

- Empty profile fields can receive document-derived values.
- A differing existing value is preserved and recorded as a conflict.
- The user explicitly chooses the current value or the résumé value.
- Imported values remain `VERIFIED_DOCUMENT` until the user verifies them.
- Verification creates another immutable profile revision.
- A second résumé cannot be imported while document facts or conflicts remain pending.

## Tests

Unit and schema coverage includes migration, malformed imports, multiple work records, profile/résumé conflicts, Unicode names, missing surnames, sensitive-inference exclusion, and all twelve synthetic blueprint personas.

Playwright loads the unpacked extension in Chromium and verifies:

- profile persistence across a panel reload;
- the complete DOCX import and verification flow;
- the complete PDF import and verification flow;
- malformed JSON rejection without profile replacement;
- continued Phase 0 Observe Mode scanning.

The committed PDF and DOCX fixtures contain fictional `.test` data and are generated by `npm run fixtures:resumes`.

## Verification

```bash
npm run verify
```

The profile remains local unless the user explicitly exports a JSON backup. Exported JSON is intentionally portable and is not encrypted; the UI warns users to store it securely.
